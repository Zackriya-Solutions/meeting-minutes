# Known gaps

- Meeting/calendar diary and Pulse project-directory linking are later phases.
- Elevated-window insertion is blocked by Windows integrity levels unless PulseTalq runs at the same level; version one detects and reports this condition.
- The cross-runtime multi-agent model is documented, but its first `integration/*` branch, durable per-task ledger, branch protections, and CI enforcement still need to be created. Until then, the coordinator must enforce the model manually.
- Exact failed-audio retention controls remain to be exposed in settings; the initial default is 24 hours.
- Existing Meetily installs coexist with PulseTalq and are left in place; nothing migrates the legacy data. `%APPDATA%\com.meetily.ai` (database, models, preferences), `%APPDATA%\meetily\notifications.json`, and `~\Music\meetily-recordings` are not read by any PulseTalq code path, so users re-download models and start with an empty database unless they use the manual database import. A consented copy-migration is a later task. See `docs/installer-verification.md` section 6.
- Installer branding gates exist for assets (`scripts/verify-installer-assets.py`) and Windows artifacts (`scripts/verify-installer-branding.ps1`), but macOS DMG and Linux deb/AppImage checks are manual, and neither gate runs in CI yet. The legacy Meetily MSI UpgradeCode has not been captured into the script's regression list.
- `frontend/public/{next,vercel,window,file,globe}.svg` are unchanged Next.js scaffold assets; the asset gate warns on them until they are removed. `frontend/src-tauri/build/ffmpeg.rs` still downloads FFmpeg from the Zackriya GitHub release.
- Windows release builds need an MSVC developer environment (vcvars64) plus a libclang that bindgen 0.69 (pinned by `whisper-rs-sys` 0.11) can drive. libclang 22 silently produces opaque structs and a `whisper-rs` compile failure; libclang 18 works. The `frontend/build*.bat` scripts hardcode `C:\Program Files\LLVM\bin`, which is absent on the current build machine. That machine has libclang 22.1.7 at `%LOCALAPPDATA%\LLVM\bin` (the user-level `LIBCLANG_PATH`) and an unpacked LLVM 18.1.8 at `%LOCALAPPDATA%\LLVM-18\bin` added on 2026-09-02; release builds must override `LIBCLANG_PATH` to the LLVM-18 folder until whisper-rs moves to a bindgen that supports libclang 22. The bundled `WHISPER_DONT_GENERATE_BINDINGS` path is macOS-only (2026-09-02).

- The NSIS setup executable carries no `CompanyName` in its PE version resource (Tauri's NSIS template only writes ProductName, FileDescription, LegalCopyright and version). The MSI `Manufacturer`, the app executable `CompanyName`, and Add/Remove Programs publisher all read PolyphronAI, so the gate treats an empty NSIS CompanyName as a warning-free pass. Adding it needs a custom NSIS installer template (2026-09-02).
- `tauri build` exits 1 after both bundles are written because the updater public key is configured but `TAURI_SIGNING_PRIVATE_KEY` is not set on the build machine. Artifacts are still valid for local verification; release builds must set the key (2026-09-02).

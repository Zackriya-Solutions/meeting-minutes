# PulseTalq installer and first-launch UX

Deep Focus applies to the whole journey, not only the app window. The installer
is the first surface a person sees. It must look and read like the app that
follows it: Blackout navigation, Readout work surface, one Hot Signal accent
where an action or an active state matters, Archivo for UI text, short direct
sentences.

Source of truth for tokens and rules: `DESIGN.md` (sections 2, 3, 8) and
`docs/pulsetalq-identity.html` (section 06, Voice and tone).

## 1. Voice and tone applied to installers

| Principle | Rule from the identity kit | What it means in an installer |
|---|---|---|
| Direct | Name the action and its result. | Buttons say what happens: "Install", "Finish", "Launch PulseTalq". No "Get started on your journey". |
| Private | Explain where data goes in concrete terms. | The one privacy line we use everywhere: "Audio stays on this device." Never "Your privacy is our highest priority." |
| Fast | Short sentences, active verbs, no pressure. | Fewest pages the toolchain allows. No exclamation marks. No "Amazing!" on the finish page. |

Copy constraints that follow from `DESIGN.md` section 8: no gradients, no
purple or blue accents, no emoji, no generic slogans, radius 3px, red only for
the mark and for the active step indicator.

## 2. Visual language: mirror the app

The app layout is a Blackout (`#0b0b0c`) sidebar on the left and a Readout
(`#f7f6f2`) workspace on the right. Every installer that lets us place imagery
should reproduce that split so the transition from installer to app is
continuous.

| Installer surface | Asset (owned by agent B) | Composition |
|---|---|---|
| NSIS welcome and finish sidebar | `frontend/src-tauri/installer/nsis-sidebar.bmp` (164 x 314) | Solid Blackout panel. Lowercase red "p" compact mark near the top, wordmark "pulse" in Readout and "talq" in Hot Signal below it. Nothing else. |
| NSIS page header | `frontend/src-tauri/installer/nsis-header.bmp` (150 x 57) | Blackout block with the red "p" mark at 24px, left aligned. |
| MSI banner (all pages after the first) | `frontend/src-tauri/installer/wix-banner.bmp` (493 x 58) | Blackout strip, mark on the left, wordmark to its right. Windows draws the page title over the banner in system font, so keep the right two thirds empty. |
| MSI dialog (welcome and completion) | `frontend/src-tauri/installer/wix-dialog.bmp` (493 x 312) | Left 164px Blackout column with mark and wordmark, remaining area Readout. Windows draws its text over the Readout area. |
| DMG background | `frontend/src-tauri/installer/dmg-background.png` (660 x 400, ship a 2x variant) | Readout field. Thin Blackout bar across the top carrying the wordmark. App icon slot at x 180, Applications folder slot at x 480, both at y 170, with a short Blackout arrow and the word "drag" between them in Archivo 12px, letter-spacing 0.14em, uppercase. |
| Installer and uninstaller icon | `frontend/src-tauri/icons/icon.ico` | The app icon. Same file for install and uninstall so the Programs list and the desktop never show two different marks. |

The installer windows are drawn by NSIS, Windows Installer and Finder in
system fonts. We cannot load Archivo there. Archivo appears only inside the
bitmaps, so all brand text lives in the images and system text stays default.

## 3. Windows: NSIS (`PulseTalq_x.y.z_x64-setup.exe`)

Configuration lives in `frontend/src-tauri/tauri.conf.json` under
`bundle.windows.nsis`.

Install mode is `currentUser`. Justification: no UAC prompt, install lands in
`%LOCALAPPDATA%\PulseTalq`, metadata in HKCU, and the updater can replace the
binary without elevation. This matches "Fast" (one fewer interruption) and
"Private" (nothing written outside the user's own profile). Managed fleets that
need Program Files can build with `perMachine`; that is a build-time switch,
not a user choice, so we do not use `both`, which forces UAC for everyone.

Journey:

1. Double-click the setup file. SmartScreen may show a publisher dialog until
   the signing certificate has reputation. The publisher name shown is the
   certificate subject, so the certificate must be issued to "PulseTalq".
2. Welcome page. Sidebar: Blackout panel with mark and wordmark. Title
   (system text, generated by Tauri): "Welcome to PulseTalq Setup". Body text
   is the Tauri default and cannot be changed without a custom template.
3. License page. Appears only because `bundle.licenseFile` is set. Shows
   `LICENSE.md`. See open decisions.
4. Install location page. Default `%LOCALAPPDATA%\PulseTalq`.
5. Progress page. Header bitmap on top.
6. Finish page. Sidebar bitmap again. Checkbox "Run PulseTalq" is checked by
   default so the first launch follows immediately.

Names the user sees afterwards:

- Start menu entry: `PulseTalq` directly under Programs (no publisher folder,
  `startMenuFolder` intentionally unset so it stays one click away).
- Desktop shortcut: `PulseTalq`.
- Settings > Apps > Installed apps: `PulseTalq`, publisher `PolyphronAI`,
  version `0.4.0`.
- Uninstaller: `uninstall.exe` in the install folder, titled "PulseTalq
  Uninstall", same icon as the installer.

## 4. Windows: MSI (`PulseTalq_x.y.z_x64_en-US.msi`)

Configuration lives under `bundle.windows.wix`. The MSI is the enterprise and
Intune path, so it is quieter than NSIS by design.

1. Welcome dialog with `wix-dialog.bmp` on the left. Title: "Welcome to the
   PulseTalq Setup Wizard" (Windows Installer default text).
2. License dialog (present because `licenseFile` is set).
3. Destination folder, default `C:\Program Files\PulseTalq`. MSI is always per
   machine, so a UAC prompt is expected here.
4. Progress and completion dialogs, `wix-banner.bmp` across the top.
5. Completion dialog with the "Launch PulseTalq" checkbox.

Add or Remove Programs entry: `PulseTalq`, publisher `PolyphronAI`, help link
and "more information" link from `bundle.homepage`.

## 5. macOS: DMG (`PulseTalq_x.y.z_aarch64.dmg`)

Configuration lives under `bundle.macOS.dmg`.

1. Open the DMG. Finder shows a 660 x 400 window with
   `dmg-background.png`. The `PulseTalq.app` icon sits at (180, 170) and the
   Applications alias at (480, 170).
2. Drag the app to Applications. The background art should make this the only
   obvious action.
3. First open triggers Gatekeeper. With an ad hoc signature
   (`signingIdentity: "-"`) the user must right-click and choose Open. This is
   a real UX cost and is listed under open decisions.
4. First launch asks for Microphone, and for Screen Recording when system
   audio capture starts. The app's own `PermissionsStep` copy already reads
   "PulseTalq needs access to your microphone and system audio to record
   meetings". Keep the system prompt strings (`NSMicrophoneUsageDescription`
   in `Info.plist`) in the same voice: "PulseTalq records your voice. Audio
   stays on this device."

Names: the app bundle is `PulseTalq.app`, the menu bar app name and the Dock
label are `PulseTalq`, taken from `productName`.

## 6. Linux: deb and AppImage

There is no installer UI. The brand surfaces are:

- `.desktop` entry `Name=PulseTalq`, `Comment=` from `shortDescription`,
  `Categories=` derived from `category: Productivity`.
- deb metadata: `Package: pulse-talq`, `Section: utils`, `Maintainer:` from
  `publisher`, `Homepage:` from `homepage`, `Description:` from
  `shortDescription` and `longDescription`.
- AppImage file name `PulseTalq_x.y.z_amd64.AppImage`; the embedded icon is
  `icons/icon.png`.

Users see these strings in GNOME Software, apt, and the application launcher.
They should read the same as the Windows Installed apps entry.

## 7. First launch: the Capture workspace

Whatever the platform, the first window is the same, and the installer visuals
were chosen to lead into it.

- Left: Blackout sidebar with the lowercase wordmark and the "+ New Call"
  entry selected (`SidebarProvider.tsx` seeds `currentMeeting` with
  `{ id: 'intro-call', title: '+ New Call' }`).
- Right: Readout workspace. The transcript panel header shows the capture mode
  title, "Type anywhere" by default, and the badge "Local and private"
  (`TranscriptPanel.tsx`). While recording, the badge switches to "Recording
  locally" and gains the Hot Signal dot.
- Two mode cards from `CaptureModeSwitcher.tsx`: "Type anywhere" and "Record
  meeting". Selecting either is the single primary action of the view.
- Onboarding steps, if not yet completed, run inside the same shell:
  permissions, model download, provider choice. Keep them on Readout with one
  Blackout primary button each.

The continuity check: the last thing the installer showed was a Blackout panel
with the red mark on the left and light space on the right. The first thing the
app shows is a Blackout sidebar with the red mark on the left and a Readout
workspace on the right. Same proportions, same two colours, same mark.

## 8. Accessibility

- Never rely on red alone. The Hot Signal mark is always accompanied by the
  wordmark text in the bitmaps, and the "Recording locally" state in the app
  pairs the red dot with words. Installer art must not encode any state or
  instruction purely in red.
- Contrast pairs to use, verified in `DESIGN.md`: Readout on Blackout 18.19:1
  (wordmark "pulse" and any text on the Blackout column), Blackout on Readout
  18.19:1 (any text on the light area), Blackout on Hot Signal 5.52:1 (text on
  a red button, if ever needed). Do not put Hot Signal text on Blackout for
  anything that must be read; the red "talq" is a logo element, not body copy,
  and the product name is repeated as system text in the installer title.
- System text stays at the OS default size and font. Do not shrink dialogs or
  override fonts in a custom NSIS or WiX template.
- Screen readers read the installer title and button labels, which come from
  `productName`. Bitmaps carry no information that is not also present as text.
- Keep the DMG "drag to Applications" instruction as text in the background
  image as well as an arrow, and keep the Applications alias name visible.

## 10. Decisions recorded on 2026-09-02

1. Publisher legal name: PolyphronAI (polyphronai.com). `bundle.publisher`,
   MSI `Manufacturer`, exe `CompanyName` and the signing certificate subject
   must all read `PolyphronAI`.
2. License page: `licenseFile` stays. `LICENSE.md` now opens with the
   PolyphronAI notice for the fork and keeps the Zackriya Solutions MIT
   notice for the original work, as MIT requires.
3. Legacy Meetily data: no in-app migration. The owner cleans up the old
   `com.meetily.ai` folders, `meetily-recordings` and registry keys by hand.
4. Upgrade policy: every future installer either installs fresh or upgrades
   the existing PulseTalq in place. Two PulseTalq entries in Installed apps
   is a blocking defect. NSIS uninstalls the previous PulseTalq version first;
   MSI relies on the identifier-derived UpgradeCode for a major upgrade.
5. macOS signing (Developer ID and notarization) and `Info.plist` usage
   strings remain open and are tracked in `project/known-gaps.md`.
6. The Parakeet model host on a `meetily.*` domain is a functional dependency,
   tracked in `docs/branding-migration-register.md`.

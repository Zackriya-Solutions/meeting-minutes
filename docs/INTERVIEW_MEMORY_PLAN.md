# Memento Interview Memory — план реализации

Статус: **реализован первый сквозной релиз; требуется продуктовая проверка на корпусе**
Версия плана: `interview_memory_v1`
Исходный проверочный материал: локальная запись `Интервью от Андрея.mp4`, 40:35.

## Цель

Превратить собеседование из записи с произвольным саммари в отдельный тип памяти Memento:

`подготовка → разговор → доказательства → проверка человеком → решение → следующий этап`.

Memento помогает сохранить проверяемые наблюдения и незакрытые вопросы, но не принимает
решение о найме, не ранжирует людей и не анализирует защищённые характеристики.

## Что показал исходный пример

- В начале не до конца определены роли нескольких интервьюеров и цель участия каждого.
- Требования к позиции формулируются уже внутри разговора, без заранее заданной рубрики.
- В одном потоке смешиваются заявленный опыт, технические мнения и решения гипотетических кейсов.
- Часть сильных утверждений остаётся без уточнения личного вклада и измеримого результата.
- Кандидат меняет решение после появления ограничения про короткую жизнь MVP — эту эволюцию
  ответа важно сохранять как отдельное доказательство.
- На вопросы кандидата, независимый debrief и явные следующие шаги почти не остаётся времени.
- Запись монофоническая и содержит несколько участников, поэтому корректная атрибуция спикеров
  является обязательным условием надёжного результата.

## Продуктовый контракт

### До интервью

- выбрать режим `Interview` до записи или после импорта;
- указать кандидата, вакансию, этап и роли интервьюеров;
- зафиксировать обязательные и дополнительные компетенции;
- описать ожидаемый результат работы на 30/60/90 дней;
- подготовить редактируемый план вопросов и ожидаемые признаки доказательного ответа;
- выбрать правила приватности, облачной обработки, индексации и хранения.

### Во время интервью

- показывать таймер блока и покрытие компетенций без автоматического скоринга;
- давать быстрые маркеры: `сильный пример`, `уточнить`, `сомнение`, `вернуться`;
- сохранять поставленный кейс, новые ограничения и эволюцию ответа;
- напоминать оставить время на вопросы кандидата и завершение;
- не отвлекать интервьюера полноценным AI-чатом поверх разговора.

### После интервью

- построить карту разговора с переходами к таймкодам;
- разделить заявленный опыт, подробный рабочий пример, мнение и решение кейса;
- собрать матрицу доказательств по компетенциям;
- для каждой записи хранить источник, таймкод, короткую цитату и статус проверки;
- явно показывать `не проверено`, а не заполнять пробелы догадками;
- провести короткий независимый debrief каждого интервьюера;
- собрать handoff: что уже проверено и что спросить на следующем этапе;
- хранить человеческое решение отдельно от AI-извлечения.

## Структура Interview Memory V1

1. **Контекст** — вакансия, этап, участники, роли и критерии успеха.
2. **Карта разговора** — блоки интервью и таймкоды.
3. **Доказательства по компетенциям** — наблюдение, тип доказательства и источник.
4. **Практические кейсы** — задача, уточнения, подход, ограничения, риски и изменение ответа.
5. **Открытые вопросы** — недостаточно подтверждённые утверждения и темы следующего этапа.
6. **Вопросы кандидата** — ожидания и важные для кандидата условия без психологических выводов.
7. **Следующие шаги** — действие, владелец и срок.
8. **Решение интервьюера** — только ручное, с отдельным журналом изменений.

Типы доказательств:

- `measured_result` — результат с проверяемым эффектом;
- `detailed_example` — конкретный рабочий пример;
- `candidate_claim` — заявление без достаточного подтверждения;
- `technical_opinion` — позиция и её аргументация;
- `case_reasoning` — рассуждение над гипотетической задачей;
- `answer_evolution` — изменение решения после нового ограничения.

## Приватность и безопасность

Интервью по умолчанию получает чувствительность `sensitive`.

- облачная расшифровка и суммаризация требуют явного разрешения для этой памяти;
- интервью исключается из общего поиска и чата, пока пользователь явно не включит индексацию;
- резюме, приватные заметки и рубрика не становятся доказательствами речи;
- предусмотрены срок хранения и каскадное удаление связанных этапов;
- кандидатский экспорт не содержит внутренних оценок и приватных заметок;
- транскрипт считается недоверенным вводом и не может менять системные инструкции extraction pipeline;
- запрещены автоматический вердикт, анализ эмоций, правдивости, акцента, возраста, пола,
  здоровья и семейного положения.

## Архитектурное направление Memento

Текущий `summary template` становится совместимым представлением более общей сущности
`MemoryWorkflow`:

```text
MemoryWorkflow
├── identity: id, version, display name
├── preparation schema
├── extraction schema
├── deterministic renderer
├── review record kinds
├── privacy defaults
└── suggestion policy requiring confirmation
```

Первым существующим workflow считается `standup_v2`, вторым — `interview_v1`.
Новые типы памяти не должны добавляться цепочкой специальных `if pipeline == ...`.

Базовые данные встречи:

- `memory_type`: `general | standup | interview`;
- `sensitivity`: `standard | sensitive`;
- далее: разрешения облачной обработки, индексации и срок хранения;
- конфигурация интервью и проверяемые записи хранятся отдельно от Markdown-рендера.

## Ребрендинг Meetily → Memento

Принцип: **Memento во всём продукте; Meetily только в явно обозначенном compatibility layer**.

Безопасно менять поэтапно:

- пользовательскую терминологию `Шаблон` → `Режим встречи` / `Тип памяти`;
- результат `Саммари` → `Память`, а для интервью → `Карточка интервью`;
- новые `MEMENTO_*` env/storage aliases с чтением старых `MEETILY_*`;
- новый каталог `Memento` с fallback на старый `Meetily`;
- user-agent, документацию и оставшиеся видимые строки.

До отдельной миграции сохраняются:

- bundle identifier `com.meetily.ai`;
- существующий Application Support каталог;
- keychain services `meetily.gateway` и `meetily.speaker-names`;
- старые каталоги записей и updater identity.

Их прямое переименование может скрыть базу, модели, gateway-токен и профили спикеров.

## Что остаётся перед production rollout

- прогнать запись Андрея и ещё 5–10 интервью через corpus/eval;
- проверить UX на реальном длинном интервью и доработать плотность панели;
- локализовать английские заголовки renderer для дополнительных языков;
- при необходимости подключить glossary к конкретному ASR provider, если он поддерживает
  phrase hints; сейчас glossary безопасно используется как контекст extraction и ручной коррекции;
- провести privacy/security review политики хранения перед включением по умолчанию в релизе.

## Проверка качества

Запись Андрея становится первым gold-примером. Для неё вручную фиксируются:

- участники и роли;
- границы вопросов и ответов;
- типы доказательств;
- компетенции и `не проверено`;
- кейсы и эволюция ответа;
- открытые вопросы и следующий этап;
- корректные технические термины.

Перед настройкой prompt собирается минимум 5–10 разных интервью. Метрики первого набора:

- точность атрибуции кандидат/интервьюер;
- доля записей с валидным доказательством;
- precision извлечённых компетенций и follow-up;
- доля корректно сохранённых `не проверено`;
- отсутствие автоматических защищённых или личностных выводов;
- сохранность ручных исправлений после повторной генерации.

## Не входит в первый релиз

- ATS и HRIS интеграции;
- сравнение и автоматическое ранжирование кандидатов;
- автоматический `нанять / отказать`;
- анализ эмоций, правдивости или языка тела;
- массовая смена bundle identifier и legacy storage без миграционного релиза.

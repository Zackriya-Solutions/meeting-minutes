# PR-45b: Hardware-aware Whisper model recommendation

## Context

Meetily defaults `large-v3-turbo` for local Whisper (set by PR-45a based on
the AISHELL-1 benchmark). That is the right default for mid/high-spec hosts,
but the average user has no way to know that and will routinely:

- Stay on the previous default (`large-v3`) on a 4-core laptop and watch
  CPU melt while CER only improves ~0.4%.
- Pick `small` (or nothing) on a 16-core / 32 GB workstation and miss the
  best possible accuracy.

PR-45b exposes a one-click recommendation that inspects the host
(`HardwareProfile::detect()`) and picks the right tier automatically,
leaning toward Chinese-meeting accuracy per PR-45a findings.

## What ships

### Backend (Rust)

1. **`frontend/src-tauri/src/whisper_engine/commands.rs`**
   - New Tauri command `get_whisper_recommended_model() -> Result<String, String>`.
   - Reuses `crate::audio::hardware_detector::HardwareProfile::detect()`
     (already wired into the audio pipeline) — no new detection code.
   - Tier mapping (Chinese-meeting-first):

     | RAM  | Cores | Recommended   | Why                              |
     |------|-------|---------------|----------------------------------|
     | ≥8GB | ≥8    | `large-v3`    | Highest accuracy, headroom for ZH |
     | ≥8GB | ≥4    | `large-v3-turbo` | PR-45a sweet spot (CER 4.8%)    |
     | ≥4GB | ≥4    | `medium`      | Mid-range balanced                |
     | else |       | `small-q5_1`  | Quantized for low-spec hosts      |

2. **`frontend/src-tauri/src/lib.rs`**
   - Registered `whisper_engine::commands::get_whisper_recommended_model`
     in the `tauri::generate_handler!` macro.

### Frontend (React + Tauri)

3. **`frontend/src/components/TranscriptSettings.tsx`**
   - Imports `Wand2` from `lucide-react`.
   - New `recommendStatus` + `recommendModel` state, `handleRecommend`
     (calls the backend) and `handleApplyRecommended` (writes through the
     existing `setTranscriptModelConfig` pipeline so `autoSave={true}` on
     `ModelManager` persists it).
   - UI: an outline button "Recommend model" appears only under the
     `localWhisper` block (right under `ModelManager`). After clicking,
     shows the suggested model name and an explicit Apply button so the
     user stays in control — never auto-applies.

### i18n

4. **Six locales** (`en-US`, `en-GB`, `zh-CN`, `zh-TW`, `ja-JP`, `ko-KR`)
   gain `settings.transcript.{recommend_label, recommend_suggested,
   recommend_apply, recommend_applied}`. Default `recommend_label` is the
   user-facing button text; the rest are status / CTA strings.

## Behavior contract

- Recommendation is **read-only** until the user clicks Apply. We never
  mutate `transcript_settings.model` automatically.
- Switching providers away from `localWhisper` resets `recommendStatus` to
  `idle` (button re-arms) — no stale suggestions linger.
- Parakeet is unaffected; `get_whisper_recommended_model` only governs
  local-Whisper model selection. A future PR can add
  `get_parakeet_recommended_model` reusing the same `HardwareProfile`.

## Verification

- `pnpm check:i18n` — locale parity.
- `pnpm test:i18n` — translation coverage (19/19 pass).
- `pnpm build` — Next.js + Tauri production build (11/11 pages).
- Rust AST review (sandbox-blocked cargo build):
  - Single new top-level `#[command]` with no side-effects beyond logging.
  - `HardwareProfile::detect()` already proven in production via the audio
    pipeline (PR-30 era); the new command just reads the cached singleton.

## Out of scope (deferred)

- Parakeet recommendation command (reuse same tier table).
- Re-running recommendation on hardware hot-plug (e.g., eGPU).
- Per-meeting override (model stays a global setting).
